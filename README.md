# Healthcare Platform

India-first healthcare platform (patient education, doctor calls, health monitoring, meal
guidance, lab tests, medicine reminders). See [BLUEPRINT.md](BLUEPRINT.md) for the full research
report, technology decisions and reasoning, compliance findings, and phased roadmap — read that
first if you haven't.

## Setup — what's done vs. what you need to do

**Already done (this session):** git repo initialized, Supabase CLI project initialized
(`supabase/config.toml`), 7 SQL migrations covering the full Phase 0/1/2 schema with row-level
security for every planned role (patient/doctor/nutritionist/lab_staff/support/admin/super_admin),
CI/CD workflow files, DPDP-aligned privacy notice and consent-flow drafts, and `apps/mobile`'s
`pubspec.yaml` + `ARCHITECTURE.md` pre-written so real Dart code can start immediately once
`flutter create` backfills the platform folders.

Two things remain that only you can do — both are outside what I'm able to do on your behalf:
installing the Flutter SDK on this machine, and creating your own hosted Supabase project
(requires your own account login). Everything else keeps moving without either.

**You need Flutter installed to continue.** Install the Flutter SDK
(https://docs.flutter.dev/get-started/install/windows), then run `flutter doctor` and resolve
anything it flags (Android Studio/SDK for Android builds; a Mac isn't needed locally for iOS
since Codemagic handles that in CI).

Once Flutter is installed, from the repo root:

```bash
flutter create --org com.yourcompany --project-name healthcare_platform \
  --platforms=android,ios,web apps/mobile
```

Replace `com.yourcompany` with your actual reverse-domain identifier (this becomes your bundle
ID / application ID — pick it deliberately, it's painful to change later, especially on iOS).

After that command finishes, tell me and I'll wire up: the `health` package (HealthKit/Health
Connect), Supabase client + auth screens (phone OTP, Google Sign-In), the app's navigation shell
per BLUEPRINT.md §4.4 (Home / Care Team & Calls / Learn / Track / Profile), and connect the CI
workflows (they're already written, just waiting on `apps/mobile` to exist).

### Supabase project (hosted)

1. Create a project at supabase.com in the **Mumbai (ap-south-1)** region (BLUEPRINT.md §2.2).
2. `supabase link --project-ref <your-project-ref>` from the repo root.
3. `supabase db push` to apply the migrations in `supabase/migrations/`.
4. Configure a phone-auth SMS hook routing to an Indian DLT-registered aggregator (e.g. MSG91) —
   do **not** use Supabase's default Twilio integration for India (BLUEPRINT.md §2.3: ~30x cost
   difference). You'll need your own TRAI DLT registration regardless of aggregator.

### Cloudflare Pages (web hosting)

Create a Pages project named `healthcare-platform`, then add `CLOUDFLARE_API_TOKEN` and
`CLOUDFLARE_ACCOUNT_ID` as GitHub repo secrets so `web-deploy.yml` can deploy to it.

### Codemagic (iOS CI)

Connect this repo in the Codemagic dashboard, add an `ios_credentials` environment group with
your App Store Connect API key, and replace the `BUNDLE_ID` placeholder in `codemagic.yaml`.
Apple Developer Program enrollment must be as an **organization** (not an individual) — health
apps require this per Guideline 5.1.1(ix) (BLUEPRINT.md §2.4/§5).

## Before real patients touch this

Three things flagged in BLUEPRINT.md §3 are genuine legal gray zones that no amount of
engineering resolves — get an Indian healthcare/tech lawyer to review these specifically before
launch: (1) the Doctor Calls module's platform-liability/ToS structuring, (2) Medicine Support if
it ever moves beyond reminders into actual sale/dispensing, (3) the Daily Monitoring Calls
module's script/scope (must stay non-diagnostic wellness coaching, not clinical monitoring).
